
Для возможности удаленного доступа используется протокол прикладного уровня под названием SSH.

Openssh это утелита, которая позвляет полльзоваться ssh. Сам ssh - это протокол сети. Есть и другие приложения позволяющие подключаться по ssh.

### Как это работает?

Есть версии SSH: 1 и 2. Openssh это утелита, которая позвляет полльзоваться ssh. Сам ssh - это протокол сети. Есть и другие приложения позволяющие подключаться по ssh. Протокол 2 поддерживает ключи _RSA и DSA_; протокол 1 поддерживает только ключи _RSA_.
* RSA универсален, подходит для шифрования и цифровых подписей. Причём создаёться два ключа: публичный и приватный. Каждый, кто знает публичный ключ может зашифровать сообщение, но расшифровать его сможет только обладатель приватного ключа.
* DSA предназначен исключительно для создания цифровых подписей, обеспечивая целостность данных, но не их шифрование.
Независимо от протокола, каждый подключающийся хост имеет собственный (обычно 2048-битный) идентифицирующий его ключ.

Рассмотрим как это работает для протокола версии 2:
1) Используется схема Диффи—Хеллмана, в результате которой получается общий ключ сеанса (который знаю только хост и клиент).
2) Из этих ключей генерируються ключи для шифрования, дешифровки в разные стороны. О способе шифрования клиент и сервер договариваються.
3) **Аутентификация сервера.** Сервер передаёт свой публичный ключ (который для шифрования RSA) клиенту в специальном формате ssh (ssh-rsa). Вместе с ним он передаёт подпись созданую из данных о данном соединении и зашифрованную при помощи приватного ключа. Каждый обладатель публичного ключа и этих данных может проверить, что это действительно обладатель приватного ключа. Таким образом это не может быть прислано злоумышлениками.
4) Машина клиент сверяет публичный ключ с известными ему (в файле `known_hosts`). Возможны несколько случаев:
	* Такого сервера нет, значит пользователь подключается впервые. Его спрашивают, хочет ли он довериться этому серверу и продолжить подключение. При ответе да, публичный ключ будет записан в файл `known_host`
	* Такой сервер есть и ключ совпадает. Тогда это тот сервер, всё супер!
	* Такой сервер есть, но ключ не совпадает. Либо сервер поменял свою пару публичного и приватного ключа, либо это злоумышленики.
5) Если соединение происходит впервые, важно проверить, что это и есть сам сервер (злоумышленики могут стать посредниками между клиентом и сервером, выдовая себя за сервер)! Клиент вычисляет отпечаток этого ключа при помощи SHA256. SHA256 — это криптографическая хэш-функция, которая преобразует любые входные данные в уникальную 256-битную (32-байтную) строку символов, называемую хэшем. Затем используется кодирование в base64. Таже пользователю показывается простая визуальная интерпретация ключа. Владелец сервера передаёт отпечаток ключа в защищённом канале, и вы можете проверить что это действительно тот сервер. Это удобнее, чем если в безопасном канале передовался полный публичный ключ. Меньше символов для сравнения. А если злоумышленик сделал его очень похожим, то хэш функция SHA256 всё равно сделает их очень разными и разница будет сразу заметна.
6) **Аутентификация  пользователя.** Сервер и клиент договариваються о способе аутентификации.
	* **По поролю.** Пользователь просто передаёт пароль в зашифрованном виде серверу и тот проверяет подходит ли он.
	* **Аутентификация по ключам.** Пользователь также создаёт своб пару ключей. После чего каким-то образом публичный ключ надо занести на сервер по безопасному каналу в файл `authorized_keys`. Каждый раз при подключении сервер будет высылать пользователю челендж: зашифрованное публичным ключом число, которое клиент должен расшифровать и вернуть, чем он показывает что он подленный клиент.
7) **Дальнейшая передача данных.** Затем все данные передаються шифруясь ключами полученными из алгоритма Диффи—Хеллмана. Это намного быстрее, чем при использовании алоритмов ассиметричного шифрования (с двумя ключами). Более того злоумышленики не смогут накопить достаточно информации для взлома ключа - он будет часто меняться. Таким образом ассиметричное шифрование используется только для аутентификации, а симметричное для всего остального.

Причём ключи сервера храняться в файлах `/etc/ssh/ssh_host_*_key` - они общие на всю машину, а ключи клиента у всех разные и лежат они в `~/.ssh/`.

Виды шифрований которые можно встретить:
* Ассиметричные:
	* RSA
	* DSA - устарел
	* ECDSA
	* Ed25519 - самый современный и рекомендуемый
* Симметричные:
	* AES. Есть несколько вариантов `aes256-ctr` - здесь 256 это размер ключа (рекомендуется 256) и ctr - означает мод работы:
		* ctr - норм
		* cbc - устарел
		* gcm - современный стандарт
	* Blowfish - устарел
	* 3DES - очень устарел
	* CAST-128 - тоже сильно устарел

### Настройка сервера

На сервер (компьютер, к которому мы будем удалённо подключаться) нужно установить пакет `openssh-server`.
Openssh это утелита, которая позвляет полльзоваться ssh. Сам ssh - это протокол сети. Есть и другие приложения позволяющие подключаться по ssh.

Настраивать доступ к серверу можно в конфигурационном файле `etc/ssh/sshd_config`.
* Protocol - выбрать версию протокола SSH. Значения 1 или 2.
* ListenAddress - По каким адрессам sshd будет подключать пользователей (т.е. мы указываем адреса наших интерфейсов которые у нас есть).
* Port - какой порт будет слушать (по умолчанию 22).
* AddressFamily - какие адреса будет использовать sshd: inet (IPv4), inet6 (IPv6), any (любые).

* PasswordAuthentication - при yes разрешает аутентификацию по паролю (не безопасно).
* PubkeyAuthentication - при yes разрешает аутентификацию по публичному ключу (безопасно).
* PermitRootLogin - можно ли подключаться за пользователя root? yes либо no.
* AuthorizedKeysFile - определяет путь к файлу с открытыми ключами. По умолчанию `.ssh/authorized_keys`. Такой путь будет у каждого пользователя в его домашней директории.
* MaxAuthTries - количество попыток аутентификации.
* LoginGraceTime - время через которое сеанс с пользователем не завершившим аутентификацию разорвёться.

* AcceptEnv - какие переменные среды могут быть изменены при подключении. Можно использовать шаблоны с `*` и `?` а также перечислять через пробел.
* AllowUsers - если используеться, то только к пользователям подходящим по данным шаблонам можно будет подключиться.
* AllowGroups - Список шаблонов имён групп через пробел. Если параметр определён, регистрация в системе разрешается только пользователям, чья главная или вспомогательная группы соответствуют какому-либо из шаблонов. Допустимы только имена групп; числовой идентификатор группы не распознаётся.
* DenyUsers - аналогично, но запрещает
* DenyGroups - аналогично, но разрешает

### На строне клиента

На машину, с которой мы будем подключаться, надо установить соответсвенно ssh клиент. Затем подключение будет иметь простой вид:
``` bash
ssh <имя_пользователя>@<IP_адрес_или_доменное_имя_удаленного_хоста>
```
При аутентификации паролем, потребуетсья ввести пароль пользователя.

Настроем аутентификацию по ключу. Создадим пару публичного и приватного ключа встроенной утилитой `ssh-keygen`. Тип ключа (rsa, ed25519, и т.д.) указачть через ключ `-t`. Итого например:
``` bash
ssh-keygen -t ed25519
```
Теперь надо передать наш публичный ключ на сервер. Можно просто вручную вставить его в файл `~/.ssh/authorized_keys`, или же при помощи утилиты `ssh-copy-id` которая автоматически его копирует через ssh. Но для этого уже нужна какае-то возможность соединения, например по паролю. Тогда можно использовать команду:
``` bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@ip-addr
```


### SSHRC

Если файл **~/.ssh/rc** существует, он будет выполняться после файлов определения переменных среды. Если этот файл отсутствует, то выполняется /etc/ssh/sshrc.

### SSH aliases

Можно создавать псевдонимы, для часто используемых подключений. Мы их записываем в файл `~/.ssh/config` или `/etc/ssh/ssh_config` для всех пользователей. В нём каждая запись имеет вид:
```
Host AliasName 
HostName 1.2.3.4 
User YourUserName 
Port YourSSHPort
```
Теперь подключение можно производить командой: `ssh AliasName`

### SCP

Команда `scp` позволяет копировать файлы из локальной машины на удалённю и наоборот.
Копирование файла с клиента на удалённую машину
``` bash
scp /srcfolder/file1 user@server:/destfolder/file1
```
Наоборот
``` bash
scp user@server:/destfolder/file1 /srcfolder/file1
```

### SFTP

Поверх ssh можно предовать файлы (протокол FTP), это становиться более защищённым SFTP (SSH file transfer protocol).
Для этого на сервере подключаем соотвествующую библиотеку для openssh. Для этого в файл `sshd_config` пишем
```
subsystem sftp /usr/lib/openssh/sftp-server
```

На клиенте мы должны примонтировать какой-нибудь каталог с удалённой машины на нашу локальную. Это делаеться при помощи утилиты `sshfs` (скачай её).
Для монтирования пишем:
``` bash
sshfs user@server:/home/userdir ~/sshfsdir
```
Размонтирование:
``` bash
fusermount -u ~/sshfsdir
```

### Важные файлы

* /etc/motd - хранит текст выводящийся при входе в аккаунт.
* ~/.ssh/authorized_keys - файл на сервере. Если используется подключение по ключам, то здесь храняться соотвествующие подключаемым пользователям ключи.
* ~/.ssh/known_hosts - файл на клиенте. Используется для аутентификации сервера, хранит их публичные ключи.
