
В этом файле должна хранится информация о всех управляемых нами устройствах.
Есть два способа задавать инвентарь, в формате `yaml` и формате `ini`. Первый подойдёт для больших систем, а второй для маленьких и он проще читается.

### inventory.ini

В таком файле всё просто в `[]` указываем группу, к которой хотим добавить хостов, а дальше на следующих строчках прописываем их ip адреса
Пример:
``` ini
[myhosts]
192.0.2.50
192.0.2.51
192.0.2.52
```
### inventory.yaml

Простой пример:
``` yaml
myhosts:
  hosts:
    my_host_01:
      ansible_host: 192.0.2.50
    my_host_02:
      ansible_host: 192.0.2.51
    my_host_03:
      ansible_host: 192.0.2.52
```
Здесь `myhost` название группы хостов, в `host` соответственно перечисляются все хосты в этой группе (словарь "имя хоста - внутренний блок").
В параметре `ansible_host` мы указываем ip адрес хоста.
Также есть такие основные параметры как:
* `ansible_user` - пользователь на управляемой машине (по умолчанию такой же, от которого мы запускаем ansible)
* `discovered_interpreter_python` - где искать интерпритатор python на управляемой машине.

##### Метагруппы
Можно также, например, создавать мета-группы, в которые включать хосты из других групп, такие группы записываются так:
``` yaml
metagroup:
  children:
    myhosts:
    another_group:
    ...
```

##### Переменные
Можно задавать переменные для каждого хоста, чтобы в последствии использовать их в конфигурации.
Можно добавлять уникальные переменные как к каждому хосту по отдельности, так и к целой группе:
``` yaml
webservers:
  hosts:
    webserver01:
      ansible_host: 192.0.2.140
      http_port: 80 # переменная специфического хоста
    webserver02:
      ansible_host: 192.0.2.150
      http_port: 443 # переменная специфического хоста
  vars:
    ansible_user: my_server_user # переменная для всех хостов
```

### Базовые команды

```
ansible-inventory -i inventory.ini --list # Проверка синтаксиса хостов
ansible myhosts -m ping -i inventory.yaml # Проверка подключения
```
