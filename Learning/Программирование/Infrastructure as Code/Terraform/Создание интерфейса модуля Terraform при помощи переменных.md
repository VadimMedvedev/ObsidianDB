
Переменные определяют интерфейс (способ настройки и взаимодействия) [[Файлы конфигурации Terraform|модуля]]. Т.е. мы указываем, какие параметры должны быть указаны для использования этого модуля. Это позволяет упростить использование модулей. Отдалить пользователя от внутренности модуля.

Пример использования переменной:
``` HCL
variable "instance_type" {
  type        = string
  description = "EC2 instance type for the web server"
  default     = "t2.micro"
}

resource "aws_instance" "web" {
  instance_type = var.instance_type
  # ...
}
```

Таким образом, в переменные можно внести настройки модуля, которые могут изменяться при использовании в разных ситуациях.

### Определение переменной

Для создания переменной мы используем блок `variable`.
Хорошим тоном считаеться всегда указывать тип переменной в аргументе `type` и описание в аргумент `description`.
Аргумент `default` опциональный. Если он указан, то необходимости указывать эту переменную при использовании метода - нет. Если не указывать, будет браться этот стандартный вариант.

Мы также можем указать несколько вложенных блоков `validation`. Каждый из них содержит условие `condition`, которому должно удовлетворять значение переменной, иначе будут выводиться ошибка `error_message` (см. [[Проверки конфигурации Terraform|проверка корректности ввода переменной]]).

Пример:
``` HCL
variable "environment" {
  type        = string
  description = "Deployment environment name"
  default     = "dev"

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}
```

Если мы используем такие секретные данные как API ключи, ssh сертификаты и т.д., то мы можем также указать аргумент `sensitive` как `true`. 

### Обращение к переменным

Чтобы обратиться к переменной мы используем выражение `var.<VAR_NAME>`. Таким образом, например, значения для аргументов ресурсов можно брать из переменных. Пример:
```
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = var.instance_type
  subnet_id     = var.subnet_id

  tags = {
    Environment = var.environment
    Name        = "${var.environment}-web-server"
  }
}
```

### Запись значений в переменные

Чтобы передать значения используемым дочерним модулям, необходимо передать их как аргументы при использовании модуля в блоке `module`.
Если мы используем переменные в [[Файлы конфигурации Terraform|рутовом модуле]], то задавать их значения можно разными способами:
* Если у переменной указано значение по умолчанию, оно будет применяться всегда, когда не указано другое.
* Terraform смотрит в файлы `*.auto.tfvars` и конкретно в файл `terraform.tfvars`.
* Из [[Переменные окружения|переменных среды]]. Terraform для переменной `var_name` будет считывать значение из переменной окружения с именем `TF_VAR_var_name`.
* Но более приоритетным источником значений переменных terraform считает аргументы при запуске `terraform apply`. Для этого используються ключи `-var` чтобы перечислить все переменные, и `-var-file` для указания файла с значениями переменных. 
* Наконец, если terraform нигде не найдёт значение переменной, он напрямую спросит у пользователя в консоли.

Отдельно рассмотрим каждый тип задания переменных:
##### Через командную строку

После команды `terraform apply` надо передать несколько раз с ключами `-var` присвоение переменных:
``` bash
terraform apply -var="instance_type=t3.medium" -var="environment=prod"
```
Или указать файл с объявлениями:
``` bash
terraform apply -var-file="production.auto.tfvars"
```
##### Определение через файл

В файле `terraform.tfvars` или файлах с расширением `.auto.tfvars` можно хранить значения для переменных. В файле это выглядит так:
```
instance_type     = "t3.large"
environment      = "prod"
subnet_ids       = ["subnet-12345", "subnet-67890", "subnet-abcdef"]
enable_monitoring = true
```
##### Из переменных окружения
Если мы хотим, например, задать значение переменной `instance_type` через переменную среды, то мы должны задать переменную среды `TF_VAR_instance_type`. Итого, запуск terraform может иметь следующий вид:
``` bash
export TF_VAR_instance_type=t3.medium
export TF_VAR_environment=staging
terraform apply
```
