
Когда все [[Объявление провайдера блоком provider|провайдеры объявлены]], то можно приступать и к описанию инфраструктуры. Для этого используються блоки `resource`, которые определяют [[Создание и управление ресурсами Terraform|ресурсы]] для terraform.

Типы ресурсов, которые мы можем объявлять, на прямую зависят от объявленных провайдеров. См. в документацию провайдеров в Terraform Registry.

### Объявление ресурса

Каждый ресурс требует тип и и уникальное название. Типы ресурсов и их аргументы опять же смотрим в документации провайдера. Но есть например встроенный тип ресурса `terraform_data`.
Так выглялидт любой ресурс:
``` HCK
resource "aws_instance" "web" {
  #...
}
```
В данном примере `aws_instance` это тип ресурса провайдера `aws`, а `web` это наше локальное имя ресурса, по котормы мы будем к нему обращаться.

В основном, в теле блока прописываються аргументы описывающие характеристики объекта данного типа. Все необходимые и опциональные аргументы прописаны в документации к провайдеру.
Приведём пример часто встречающегося аргумента:
##### Ограничения по времени

Одним из часто встречающихся аргументов является `timeouts`. Он определяет, сколько terraform будет ждать выполнение той или иной операции, пока не выдаст ошибку истечения времени ожидания. Конечно, набор операций может разнится от провайдера к провайдеру, но стиль записи принято саблюдать следующим:
* Лимиты времени указываються во вложенном блоке `timeouts`.
* Он содержит аргументы, соответсвующие операциям terraform над объектом.
* В качества значения, они принимают строки в виде: `"60m"`, `"10s"` или `"2h"`.
Пример ресурса с таким блоком:
``` HCL
resource "aws_db_instance" "example" {
  # ...

  timeouts {
    create = "60m"
    delete = "2h"
  }
}
```

### Мета аргументы и блоки

Но в каждом блоке resource могут быть прописаны мета аргументы, общие для всех блоков `resource`. Они определяют поведение terraform при их создании. Рассмотрим несколько основных таких аргументов:
##### Использование провайдера по псевдониму

Как уже обсуждалась, в одном модуле terraform [[Объявление провайдера блоком provider|можно создать несколько провайдеров одного типа]]. Для этого используються аргументы `alias` в блоках `provider`. Чтобы теперь выбрать конкретный провадер для ресурса, нужно указать мета аргумент `provider` со значением в виде `"<PROVIDER_NAME>.<ALIAS>"`.
##### Определение зависимостей

В большенстве случае, terraform сам определяет зависимости ресурсов и создаёт параллельно те, которые не зависят друг от друга. Но иногда становиться необходимым указывать ему, без установки какого ресурса, нельзя приступать к текущему.
В аргументе `depends_on` мы задаём список из ресурсов, которые должны быть установлены первее:
``` HCL
resource {
  depends_on = [ <resource reference> ]
}
```

### Удаление одного ресурса

Для удаления одного конкретного ресурса достаточно удалить его из файла конфигурации и написать команду `terraform apply`, которая примет все изменения. После чего такого ресурса уже не будет в реальной инфраструктуре.
ВАЖНО также затереть все ссылки на этот ресурс из других ресурсов. Можно проверять, не осталось ли ссылок при помощи команды `terraform validate`.

### Удаление всей инфраструктуры

Это осуществляется при помощи команды `terraform destroy`. При этом очистится только реальная инфраструктура, а конфигурационный файл останется прежним. Его содержимое сново можно будет выстроить при помощи команды `terraform apply`.
