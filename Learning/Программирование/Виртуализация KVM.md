
### Основы

**Гипервизором** называеться ПО, которое позволяет отделить физическое оборудование от приложений, запущенных в операционной системе. 
Таким образом получаеться заупстить на одном хосте (машине) несколько гостевых операционных систем, которые не знают что они эмулируються и работают как обычные машины. Гипервизор изолирует их всех, чтобы они могли работать параллельно и не мешать друг другу. 
Такой подход конечно съедает некоторую вычеслительную мощность для поддержания такой абстракции, но у виртуализации есть свои плюсы которые перекрывают минусы и все компании в той или иной степени её используют. Плюсы:
1) Такие сервера легко создавать и уничтожать, что позволяет легче их развёртывать и даже автоматизировать это.
2) Изоляция сервисов друг от друга и установление конфигураций отдельно для каждой ВМ, что позволяет избавиться от конфликтов ПО. Например использование более соответсвубшей операционной системы для того или инго ПО.
3) Безопасность. Взломав одну виртуальную систему, злоумышленники не получат доступа к остальным. 
4) Overcommitting. Выделенная память для виртуальных машин в сумме может превышать память хоста, что называеться overcommitting, что добавляет гибкости ВМ. Также можно поступать и с оперативной памятью и с ресурсами процессора.

### Основные инструменты виртуализации

Одна из лучших систем виртуализации сейчас от компании VMware. Есть как ПО, чтобы запускать с машины виртуалки, так и полноценная "операционная система" Vsphere которая устанавливаеться на несколько машин, эти машины объединяються в кластеры, а потом используються как полноценное облоко, платформа на которой безраздумий можно ставить сколько угодно виртуалок, пока ресурсы кластера позволяют. Но использование такого кластера стоит большие деньги...

Наиболее популярна среди масс VirtualBox, поскольку он полностью бесплатный и интуитивно понятный. Но и в тоже время он плоский - в нём мало функционала.

KVM (Kernel-based Virtual Machine) - ПО которое обычно легко установить на любой Linux. Удобен для автоматизации и использует преимущества ядра Linux, при этом абсолютно бесплатный. Большенство облачных провайдеров, которые сдают в аренду виртуальные машины PVS (Virtual Private Server) используют зачастую именно KVM.

### Три базовые абстракции

QEMU - это движок, который эмулирует саму машину.
KVM - модуль ядра Linux для работы виртуализации. Это гипервизор.
libvirt - удобное расширение, которое делает использование qemu приятным и добавляет новые фишки.

Дело в том, что если бы эмуляцию машины сделали чисто как ПО, то работало бы это всё медленно. Для быстрой работы нужно использовать более низкие, аппаратные решения. Таким образом процессоры имеют блоки для поддержки виртуализации аппаратно, т.е. на самом низком уровне, что сильно ускоряет виртуализацию. KVM это как раз таки модуль ядра Linux, который позволяет использовать эту аппаратную часть процессора. QEMU - это само приложение, которое может и не использовать KVM, но тогда оно будет намного медленне. libvirt вообще не заточен конкретно под qemu а используеться и для других систем виртуализации. Для всех них он организует единный интерфейс. Таким образом научившись управлять libvirt мы сможем управлять любым поддерживаемым движком виртуализации (а их много).

### Установка

Для начало, надо в bios активировать возможность аппаратной виртуализации. Для каждой материнки эта опция может называться по разному. Но обычно там есть слово virtualization и надо поставить enable.

Дальше надо включить модуль kvm. Вообще проверить включен ли он, можно командой:
``` bash
lsmod | grep kvm
```
lsmod - выводит все запущенные модули ядра. Поскольку ядро linux подгружает модули динамически, если не было установлено ПО его требующего, его может и не быть.

Если модуль не запущен, то найдём его и подгрузим. Все модули ядра лежат в директории /lib/modules, так что ищем в ней:
``` bash
find /lib/modules/ -type f -name "*kvm*"
```

Надо установить также пакеты: (движок виртуализации:) qemu, (общий интерфейс для всех ситсем виртуализаций:) libvirt, (вспомогательные утилиты:) virt-install, ebtables, dnsmasq, dmidecode, virt-viewer.

Ставим libvirt в автозагрузку:
``` bash
systemctl start libvirtd
systemctl enable libvirtd
```

Для того чтобы пользоваться сервисом libvirt юзер linux должен быть добавлен в группу этого приложения:
``` bash
usermod -aG libvirt vadim
```

### Образы дисков

Нам нужно где-то хранить данные виртуальной машины, и это можно делать большим количеством способов: LVM тома, расшаренные директории (NFS), специальные файловые системы и т.д.
Сейчас мы рассмотрим способ использования в качестве образа диска обычный файл.
Есть несколько форматов для образов, основные и интересные два:
1) raw - файл сразу с зарезервированным дисковым пространством. Т.е. если мы хотим ВМ с 50 гигами памяти и образом диска в формате raw, то на хосте будет лежать файл весом 50 гигов. С одной стороны ограничения для роста ВМ, а с другой стороны у неё всегда будут зарезервированные для неё 50 гигов, хостовая машина не сможет заять их.
2) qcow2 - файл будет увеличиваться по мере заполнения. Намного более гибкий чем raw. По сути overcommitting памяти. Виртуалка будет думать, что может расти хоть на сколько (на сколько она думает у неё прикреплён диск), хотя на самом деле свободного дискового пространства на хосте может быть меньше.

### Основные команды qemu

Все команды qemu начинаються с qemu-...:
* qemu-img - обащая утилита для работы с образами дисков
	1) convert -f <формат 1> -O <формат 2> <файл 1> <файл 2> - конвертирует файл 1 образа диска из формата 1 в формат 2 и сохраняет его как файл 2.
	2) create -f <формат> <файл> <размер> - создаёт файл образ диска с указанным форматом нужного размер (например 10 G). Сохраняет его как <файл>.
	3) info <файл> - выводит краткую информацию об образе диска.

### Работа с libvirt

Можно посмотреть все поддерживаем технологии libvirt:
``` bash
virsh -V
```
Все гипервизоры, способы хранения данных, сетевые технологии.

Чтобы зайти в libvirt пишем команду virsh (надо находиться в primary группе libvirt). Откроется внутренний интерфейс со своими командами. Такой формат совсем не удобен для виртуализации
Более того, можно использовать libvirt не заходя во внутреннее окружение virsh, а используя команды так:
``` bash
virsh command
```

libvirt использует файлы в формату xml для хранения данных, конфигов. Он похож на HTML, но если у HTML теги строго установленные, специальные для отображения данных на странице, то у XML они могут быть произвольными, такие какие нужны для передачи данных.

libvirt поддерживает мультипользовательский режим, т.е. в зависимости от того, под каким юзером ты заходишь, будут показываться ВМ только этого юзера.

##### Работа с сетями

Команды virsh:
1) net-list - отображает все включенные доступные виртуальные подсети, к которым мы можем подключать наши гостевые машины. Ключ --all показывает даже не активные.
2) net-dumpxml <подсеть> -  показывает текст в формате XML описывающий этот сетевой интерфейс.
3) net-define <XML файл> - добавляет новую подсеть описанную в XML файле.
4) net-edit <подсеть> - открывает соответсвующий XML файл в редакторе для внесения правок (редактор указанный в переменной окружения EDITOR). После сохранения и выхода система сразу применит изменения.
5) net-start <подсеть> - активирует выбранную сеть.
6) net-autostart <подсеть> - сеть будет автоматически запускаться при запуске системы. Для отключения автостарта используем ключ --disable с этой командой.

XML файл для виртуального сетевого интерфейса имеет стандартно следующий вид:
``` XML
<network>
	<name>network1</name>
	<forward mode='nat' />
	<bridge name='virbr0' stp='on' delay='0' />
	<ip address='192.168.122.1' netmask='255.255.255.0'>
		<dhcp>
			<range start='192.168.122.200' end='192.168.122.254' />
		</dhcp>
	</ip>
</network>
```
Заметим, что здесь мы указываем тип сети - nat. Т.е. адресса наших виртуальных машин подключённыъ к ней будут при выходе в интернет ретранслироваться (и даже не сколько раз, если хост тоже находиться под натом). Также можно поставить тип и сетевого моста, тогда машины будут в одной сети с хостом.
Чтобы применить эти настройки, можно не находясь в интерактивном режиме применить команду:
``` bash
virsh net-define [path-to-file.xml]
```

### Настройка хранилищ (pool)

В libvirt есть множество способов хранить данные для виртуальной машины (nfs, обычные файлы, директории, lvm тома и т.д.). Такие хранилища называют пулами (обобщённое название), в них храняться уже отдельные файлы и диск для ВМ.

Команды для создания и редактирования пулов практически полностью совпадают с командами для сетей, только слово net заменяеться на pool: pool-list, pool-dumpxml, pool-define, pool-edit, pool-start, pool-autostart. Все настройки пулов также храняться в XML формате.

Рассмотрим XML файл для пула типа директория (все образы дисков будут храниться в директории на хосте):
``` XML
<pool type="dir">
	<name>pool1</name>
	<target>
		<path>/QEMU/pool1</path>
	</target>
</pool>
```

### Создание ВМ через virt-install

virt-install - это надстройка над libvirt написанная на python, позволяешься в удобном формате создавать виртуальные машины, а не через создание огромного XML файла.
Рассмотрим команду которая создаёт ВМ использую утилиту virt-install
``` bash
virt-install --name template1 --memory 2048 --vcpus=2 --cpu host --cdrom /QEMU/images/debian-13.2.0-amd64-netinst.iso --disk pool=pool1,size=30,bus=virtio,sparse=true,cache=none,io=native --network network=network1 --virt-type kvm --graphics=vnc --osinfo debian13
```
Здесь мы указываем название ВМ (template1), выделенную для неё оперативную память (memory), количество ядер процессора (vcpus), образ диска, который машина как бы будет видеть в своём дисководе (cdrom), настройки диска: пул в котором будет создан образ диска, его размер, sparse зарезервирует место на диске при false, иначе файл образа будет весить столько же сколько вся система; сеть: к чему будет подключена ВМ. Также мы говорили, что libvirt может работать с разными виртуализациями, так что в virt-type можно выбрать конкретный тип. Параметр graphics принимает способ передачи информации с создаваемой виртуальной машины, в данном случае vnc это протокол трансляции видео. В osinfo указываем название используемой операционной системы (можно придумать любое).

Сразу после установки libvirt инициализирует директорию, из которой был взят образ диска, как пул.

После установки следует сделать следующую последовательность команд:
``` bash
virsh destroy template1
virsh edit template1
```
И удалить блок данных о cdrom. Мы это делаем, поскольку после установки ВМ уже не нужен установочный диск.
Перед редактированием мы выключили систему, чтобы сделать правки в машине. Очевидно это надо делать каждый раз перед внесением правок (мы же не меняем оперативную память в ПК пока он включен, для этого мы его выключаем).

У меня возникли проблемы с усановкой, из-за того что похоже hyprland не захотел запускать окно с виртуалки из-за того что права рабочего стала не совпадали с пользователем, от которого я это всё делал (root). У меня получилось простое решение: я просто зашёл через графический интерфейс (программа KVM) и смог спокойно зайти в установку.

### Работа с ВМ

В терминалогии libvirt виртуальные машины называються **доменами (domain)**.

Всё теже команды что и для пулов и сети можно использовать для доменов, но без преписки net или pool (всё таки домены это основной объект в libvirt): define, autostart, start, dumpxml, edit, list.
Команды которые мы ещё не упомянали:
* destroy <домен> - принудительно останавливает работу ВМ (по сути выключает питание).
* undefine <домен> - удаляет указанный домен (для начала нужно выключить домен).
Аналогичные команды есть и для пулов и для сетей, хотя есть и исключения (например undefine для дисков, поскольку это не какой-то объект libvirt заданный XML файлом, а обыкновенный файл на диске, для этого используеться команда vol-delete).

При помощи утилиты virt-viewer можно подключиться к любой ВМ. То есть экран ВМ будет транслироваться на наш хост.

При помощи команды virt-clone (из пакета virt-install) можно легко клонировать наши ВМ. Для этого например пишем следующую команду:
``` bash
virt-clone --original template1 --name server1 --auto-clone
```
Здесь в original мы указываем изначальный домен, в name как будет называться новый домен и напоследок ключ auto-clone говорит о том, что все правки будут сделаны автоматически (по типу изменения mac адреса и т.д.).

### Работа с дисками

В libvirt диски называються volume.

Команды:
1) vol-list <пул> - выводит все диски лежащие в данном пуле
2) vol-info --pool <пул> <диск> - выводит информацию о диске (надо указать пул, в каком именно мы ищем).
3) vol-delete --pool <пул> <диск> - удаляет заданный диск.
