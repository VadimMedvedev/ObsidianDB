
Во время написания этой статьи, Российский трафик блокируется на Terraform Registry, из-за чего, при [[Работа с провайдерами в Terraform|установке провайдеров]], может возникнуть следующая ошибка:
```
╷
│ Error: Invalid provider registry host
│ 
│ The host "registry.terraform.io" given in provider source address "registry.terraform.io/hashicorp/http" does not offer a Terraform
│ provider registry.
╵
```

Причём, явно причина в ней не указана.

### Способ обхода блокировки

Все уже установленные провайдеры храняться в `~/.terraform.d/plugins`.
В данном случае здесь уже скачено два провайдера:
```
.
└── registry.terraform.io
    ├── dmacvicar
    │   └── libvirt
    │       └── 0.9.1
    │           └── linux_amd64
    │               └── terraform-provider-libvirt_0.9.1_linux_amd64.zip
    └── hashicorp
        └── http
            └── 2.0.0
                └── linux_amd64
                    └── terraform-provider-http_2.0.0_linux_amd64.zip
```
Т.е. каждый провайдер лежит по следующему пути, составленному из:
1) registry.terraform.io - название сервера, с которого был скачен провайдер, данный сервер - сам публичныый сервер Terraform Registry, который и не даёт скачать провайдеры.
2) dmacvicar - [[Перечисление провайдеров в блоке terraform|namespace]], в данном случае, создатель этого провайдера
3) libvirt - название платформы, для которой сделан провайдер
4) 0.9.1 - версия провайдера
5) linux_amd64 - ОС и архитектура процессора

Когда мы запускаем команду `terraform init`, она идёт по этому пути и ищет нужного провайдера, если не находит, то идёт скачивать его. 
Идея обхода: искусственно создать нужные директории, и поместить каким-либо образом скаченный файл провайдера в эту директорию. Тогда terraform найдя этот файл, не пойдёт его скачивать самостоятельно и успокоиться.

Этот файл можно скачать например из githubа разработчика или ещё где поискать.
