
**Terraform** это инструмент для работы с облачными и локальными (on-prem) ресурсами. Он позволяет выстраивать инфраструктуру объектов при помощи кода (IaC - infrastructure as code).

По итогу, вся инфраструктура записывается в файле, который можно легко прочитать и отредактировать, тем самым изменив реальную архитектуру.

Конфигурационные файлы terraform являються делкаративными!!! То есть мы описываем в них что мы хотим получить, а terraform сам составляет и реализует подходящий план.

### Как он работает?

Он взаимодейтсвует с ресурсами платформы через API этих платформ. **Провайдеры (providers)** позволяют terraform работать с любого вида платформами, главное, чтобы у них было API.

Сообщество разработала уже тысячи различных провайдеров для работы с разными сервисами и платформами. Их всех можно посмотреть в **Terraform Registry**. Среди них: AWS, Azure, Kubernetes, libvirt, GitHub и т.д.

Есть три стадии работы terraform:
* Мы изменяем конфигурационный файл инфроструктуры и говорим применить изменения terraform.
* Он строит план: какие были добавлены ресурсы, какие удалены и т.д. Он простраивает как это должно быть реализовано.
* В конце концов, он это делает.

### Отслеживание изменений

Всё состояние инфраструктуры записывается в state файлы. Поним можно отследивать как менялась вся инфраструктура.

### Модули

Терраформ поддерживает некоторые частоиспользуемый компоненты, которые можно найти в Terraform Registry. Они уже опредяют целую инфраструктуру.

### HCP Terraform

Это SaaS (Software as a Service) сервис, который позволяет запускать terraform на удалённом сервере. Его можно синхронизировать с любой системой контроля версий (VCS), чтобы при коммитах, новые изменения автоматически применялись к инфраструтуре.
Также HCP Terraform предлагает API для самостоятельного введения его в процессы CI/CD.

### Фишки terrafrom

* **Развёртывание на нескольких облоках.** Для отказоустойчивости, можно создавать инфраструктуру сразу на нескольких платформах, разлинчых облачных вервисах и т.д. Правада к ним всем нужен свой индивидульный подход.
* **Инструменты для развёртывания, масштабирования и мониторинга.** 
* **Автоматизация.** Можно создать инфраструктурную модель, при помощи которой, можно просто изменять инфраструктуру меняя готовые модули (собственные или других пользователей).
* **Контроль соблюдения политики.** Встроенный в terraform инструмент Sentinel позволяет настраивать права изменения инфраструктуры, согласно с политикой компании (policy as code PaC). Неправомерные изменения не будут применятся. Он доступен в Terraform Enterprise и HCP Terraform.
* **Оценка стоимости инфраструктуры.** Есть встроенные инструменты для оценивания стоимости инфраструктуры на той или иной платформе.
* **Автоматическая настройка сети.** В терраформ есть инструменты для автоматизации настройки сети на создаваемых ресурсах.
* **Развёртывание параллельных инфраструктур.** Это может пригодиться, для тестирования новой версии, перед выкатом её в прод и т.д.
