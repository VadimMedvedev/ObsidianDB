
HBA = **Host-Based Authentication**.
Этот файл решает: кто может подключаться, откуда и как.
Он для каждого [[Кластеры в Postgresql|кластера]] свой и лежит в корневой директории каждого кластера.

### Записи

В этом файле все строки имеют формат:
```
TYPE  DATABASE  USER  ADDRESS  METHOD
```

Рассмотрим каждый столбец по отдельности:
* `TYPE` содержит тип соединения: либо локально `local`, либо по сети `host`.
* `DATABASE` - определяем к каким базам данных разрешён доступ. Примеры:
	* `all` - ко всем
	* `db1` - к конкретной одной
	* `db1,db2,db3` - через запятую несколько
	* `/db_.*/` - регулярки
	* `sameuser` - для того чтобы какому-то пользователю `pety` была доступна одноимённая бд `pety`.
	* `replication` - специальный режим для репликации. Об этом в будущем
* `USER` - к какому пользователю можно подключится (стиль записи как и в прошлом столбце). Из необычного `+admins` означает возможность подключения ко всем пользователям группы `admins`.
* `ADDRESS` - указывается, если тип `host`. Адреса из какой подести подподают поо это правило:
	* `0.0.0.0/0` - все ip адреса подходят
	* `192.168.1.0/24` - из этой подсети
	* `10.0.0.5/32` - только один
* `METHOD` - метод аутентификации. Бывают следующих видов:
	* `trust` - не спрашивает ничего, всегда пускает
	* `md5` - чтобы зайти за конкретную роль, требуется ввести её пароль.
	* `peer` - через Linux пользователя. Работает только при `local`. Тогда если имя пользователя в ОС совпадает с именем некоторой роли в кластере, то он заходит через неё, пароль не требуется.
	*  `reject` - явный запрет

Проверка правил происходит сверху вниз, пока данные пользователя не совпадут с одним из правил. Последующие правила проверятся не будут

### Тонкости

Удалённые пользователи могут отсеятся на этапе `postgresql.conf` (если он не [[Файл postgresql.conf|слушает соответсвующий адрес и порт]]).
В одном кластере может быть создано сразу несколько баз данных и ролей (внутренние пользователи кластера), так что это имеет смысл.
Если доступ разрешён пользователю к этой базе данных за конкретную роль, это ещё не значит, что у этой роли есть хоть какие-нибудь права на эту базу данных (внутренняя настройка прав доступа).
