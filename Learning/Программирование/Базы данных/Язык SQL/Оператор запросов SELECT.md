
SELECT - оператор запроса на выборку. Он выводит **выборку данных**, т.е. таблицу, которая содержит искомые записи.

### Синтаксис простого запроса SELECT

``` SQL
SELECT [ALL | DISTINCT] {* | [список полей]}
FROM Источник записей запросов
[WHERE условие отбора записей]
[GROUP BY список полей групировки]
[HAVING условие (фильтр) для группы]
[ORDER BY Список полей сортировки [ASC|DESC]]
```

Здесь обязательными является перечисление полей, которые надо вывести, и таблица откуда мы это берём.

ALL (по умолчанию) - выводит все записи
DISTINCT - не выводит записи дубликаты
\* - обзначает вывод всех полей
WHERE - оставляет только те записи, которые удовлетворяют указанному условию. В условиях используються обычные предикаты сравнения: =, != (или <>), <, <=, >, >= и логические операторы OR, AND, NOT. В обще логика здесь трёхзначная, булевое значение может быть NULL(т.е. не получаеться определить).
ASC и DESK - по возрастанию и по убыванию соответсвенно (выставляется для каждого поля отдельно)

### Написание условий в WHERE

 В обще логика здесь трёхзначная, булевое значение может быть NULL(т.е. не получаеться определить).
 
В условиях используються обычные предикаты сравнения: =, != (или <>), <, <=, >, >=.
Логические операторы OR, AND, NOT.
Предикат **поле BEETWEEN нижняя AND верхняя граница** - определяет лежит ли значение в заданном диапазоне (границы включаються).
Предикат **поле LIKE маска** - проверяет удовлетворяет ли строчка регулярному выражению.
Предикат **поле IN (список)**, лежит ли значения поля в списке. 

### Псевдонимы

Мы указываем псевдоним записью:
``` SQL
name AS alias
name alias 
```
Теперь обращаться к этой таблице можно через `alias`. Если указали псевдоним таблицы, то обращение к полю этой таблицы: `t_alias.name`.
Можно вводить псевдонимы для полей, тогда в выводе таблицы мы будем видеть название столбца именно как псевдонима

### Вычисляемые поля

В SELECT в качестве выводимых полей можно выводить некоторые вычисляемые значения, например:
``` SQL
SELECT id, name, price, ROUND(price * 0.8) AS "Оптовая цена"
FROM products
```

### Функции

В прошлом примере использовали функцию ROUND, вообще в SQL есть много различных функций:
**Для работы с датами:** CURDATE, CURTIME, DAY, MONTH, YEAR, HOUR, ...
**Математические:** SIN, COS, TAN, COTAN, ABS, POW, ROUND
**Текстовые:** LEFT(text, n) (первые n символов взять), RIGHT, MID, CONCAT, ...
**Тернарный**: IF(условие, значение если True, иначе)
Ну и с другими типами данных тоже есть

### Механизм групировки

При использовании GROUP BY, БД находит уникальные поля (группы полей) из всех записей из выбранных полей, и все записи тогда будут раскладываться по этим "кучкам".

### Функции агригации

Если мы используем групировку, то мы можем в таблице добавить столбец, представляющий из себя какие-то значение соответсвующие целой группе товаров. 
Это функции: SUM, COUNT, MIN, MAX и т.д.
Пример:
``` SQL
SELECT category, SUM(price)
FROM products
GROUP BY category
```
Сумма всех цен на предметы одной категории

##### Использование без GROUP BY
Тогда вся выделяемая таблица будет считаться одной группой, и по всем записям будет вестись функция агрегации.

### Использование нескольких таблиц

В запросе можно использовать несколько таблиц. Для удобства для каждой можно ввести псевдоним. Потому что теперь к каждому полю мы будем обращаться как `table_name.name`.

### Объединение таблиц

После введения таблицы после `FROM` мы можем указать ключевое слово `JOIN` и указываем таблицу для соединения. После мы указываем `ON` и мы указываем как мы будем соединять записи из одной и другой таблицы.
``` SQL
SELECT *
FROM table1 t1 JOIN table2 t2 ON t1.pkey == t2.fkey
```
Получится таблица где каждая запись получается объединением полей записей первой таблицы и полей второй.
В этом примере, для удобства, мы ещё задали псевдонимы для таблиц.
`LEFT JOIN` - объединяет каждую запись из левой таблицы с элементом из правой подходящее по условию после `ON`. Если несколько записей подходят, то для одной записи из левой таблицы создастся несколько запсией в склееной.
`RIGHT JOIN` - аналогично, но наоборот.
`INNER JOIN` - соединяет все возможные комбинации
Разница!!! `LEFT JOIN` создаст записи для всех (!!!) записей слева, даже к которым нечего прикреплять справа (просто NULL припишет).
`JOIN` по умолчанию работает как `INNER JOIN`, это синонимы.
