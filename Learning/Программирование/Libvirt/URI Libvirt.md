
URI - это строка, которая однозначно идентифицирует гипервизор (виртуализацию) для управления. Это основной способ указать, к какому механизму виртуализации и где нужно подключиться.

Общая структура URI:
```
driver[+transport]://[username@][hostname][:port]/[path][?extraparameters]
```

Здесь драйвер, это способ виртуализации:
* `qemu` - Управление виртуальными машинами QEMU/KVM
* `lxc` - LXC контейнерыp
* `vbox` - через VirtualBox 
* и т.д.
Способ подключения (transport):
* Пропускается, если это на локальной машине
* `ssh` - подключение через ssh
* `tcp` - незашифрованный TCP
* и т.д.
Путь `path` определяет конекст управления (не у всех драйверов указывается):
* `system` - глобальный уровень, т.е. виртуальные машины всей машины. Требует прав `sudo`.
* `session` - пользовательские машины, только их.

Примеры:
* `qemu:///system` - локальное подключение к системным ВМ QEMU/KVM
* `qemu:///session` - тоже самое, но к лично пользователиським ВМ
* `qemu+ssh://root@192.168.1.100/system` - удалённое подключение по ssh

Выбор uri по умолчанию зависит от сборки libvirt и от пользователя от лица которого вы сидите. 
Посмотреть к чему подключён libvirt по умолчанию можно:
``` bash
virsh uri
```
Можно вручную указать uri к которому подключить libvirt:
``` bash
export LIBVIRT_DEFAULT_URI="qemu:///system"
```
Или же указывать при команде нужный uri:
``` bash
virsh -c qemu:///system
```
