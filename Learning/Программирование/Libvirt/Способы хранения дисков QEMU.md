
Нам нужно где-то хранить данные виртуальной машины, и это можно делать большим количеством способов: LVM тома, расшаренные директории (NFS), специальные файловые системы и т.д.
Сейчас мы рассмотрим способ использования в качестве образа диска обычный файл.
Есть несколько форматов для образов, основные и интересные два:
1) raw - файл сразу с зарезервированным дисковым пространством. Т.е. если мы хотим ВМ с 50 гигами памяти и образом диска в формате raw, то на хосте будет лежать файл весом 50 гигов. С одной стороны ограничения для роста ВМ, а с другой стороны у неё всегда будут зарезервированные для неё 50 гигов, хостовая машина не сможет заять их.
2) qcow2 - файл будет увеличиваться по мере заполнения. Намного более гибкий чем raw. По сути overcommitting памяти. Виртуалка будет думать, что может рости хоть на сколько (на сколько она думает у неё прикреплён диск), хотя на самом деле свободного дискового пространства на хосте может быть меньше.
Это форматы разработанные именно под KVM и QEMU.

Помимо основного различия в размере файлов, формат `qcow2` имеет следующие приемущества:
* Можно сохранять состояние диска (создание снепшотов)
* Можно создать образ, который “наследуется” от другого
* Поодерживает сжатие
Подкопотом этот формат сложно устроен. Как видно из выше описанного, каждый файл может быть основан на другом qcow2 файле, притом новый файл по сути будет содержать изменения на первый файл. Короче сложная система.
