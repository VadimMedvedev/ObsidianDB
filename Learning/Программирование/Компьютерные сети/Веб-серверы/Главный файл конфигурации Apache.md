
В файле `/etc/apache2/apache2.conf` лежат самые основные настройки Apache.
Рассмотрим их:
##### Базовые настройки
`ServerRoot "/etc/apache2"` - где лежат конфигурационные файлы, их корневая директория
`User www-data` - пользователь, от которого работает Apache
`Group www-data` - первичная группа этого пользователя
`Define LOG_DIR /var/log/apache2` - задаёт переменную окружения прямо в конфигурации (обычно прописываются в файле envvars). Затем к ней можно обращаться дальше, как обычно
`Listen 80` - говорит какой порт вообще говоря будет слушать (по умолчанию 80 - http, 443 - https). Можно указать несколько.

##### Основные настройки
`ServerName localhost` - как Apache будет именовать себя в ошибках. Более того, это устанавливает доменное имя сайтов по умолчанию (в последствии можно будет менять, для того чтобы можно было их отличать пользователям).
`ServerAdmin webmaster@example.com` - указывает email адрес администратора, который будет показываться при ошибках.
`DocumentRoot "путь/к/директории"` - указывает, какая директория на устройстве будет соотвествовать корневой директории на сайтах.
`DirectoryIndex index.php index.html` - файлы в директориях, которые будут открываться, если пользователь будет запрашивать директорию.

##### Логирование
`ErrorLog ${LOG_DIR}/file-error.log` - указание файла с логами самого Apache
`LogLevel warn` - назначает уровень логирования (в порядке увеличения подробности: `emerg`, `alert`, `crit`, `error`, `warn`, `notice`, `info`, `debug`).

##### Ограничения
`Timeout 300` - определяет в секундах время ожидания. Причём тут время ожидания настраивается сразу нескольких функций: сколько времени ждёт сервер отправки полного запроса (он может занимать нескольк пакетов), сколько ждать между загрузкой файлов, время ожидания от CGI скрипта.
`KeepAlive On` - включает или выключает работу постоянных подключений. Продолжительное подключение использует одно TCP соединение для передачи нескольких http запросов (а не как по умолчанию один запрос одно соединение TCP, это очень накладно для сети и сервера).
`KeepAliveTimeout 5` - время, которое отсчитывается с последней отправки запроса, и при истечении закрывает TCP подклчюение. При маленьких значениях: будут не успеваться делаться запросы. При больших значениях: все на сайт не влезут, кому-то придётся ждать
`MaxKeepAliveRequests 50` - максимальное число продолжительных TCP подключений (чтобы не перенагружать систему)

##### Включения конфигураций
Чтобы включить и другие файлы конфигурации, помимо основго, существуют две команды:
`Include Ports.conf` и `IncludeOptional Ports.conf`
Основное различие в том, что `Include` - обязательное включение конфигурации. Если такого файла нет, или ни один файл не подходит по шаблону (можно вписывать шаблоны, [[глоббинг]]), то он ругнёстя и выдаст ошибку.
Но при `IncludeOptions` он ругаться не будет, это "опционально".

##### Настройка директорий
Настройка директорий происходит через блок `Directory`, выглядит так:
```
<Directory путь/к/директории>
	Настройки директории
</Directory>
```
Между двумя тегами мы прописываем настройки, которые будут применяться рекурсивно ко всем директориям.
**Важно, что таких блоков можно прописать несколько. И каждый будет переопределять настройки предыдущих.**
Параметры:
`Require ...` - какие пользователи смогут получать доступ к ресурсам этой директории:
* `all granted` - все
* `all denied` - никто
* `ip 192.168.1.0/24` - с конкретными ip адресами
* `user username` - конкретный пользователь
* `valid-user` - все авторизованные пользователи
`Options op1 op2 ... opn` - настройки для этих директорий:
- `None` - никаких дополнительных возможностей
- `Indexes` - показывать список файлов директории, если нет index.html
- `FollowSymLinks` - разрешить следовать по символьным ссылкам
- `ExecCGI` - разрешить выполнение CGI-скриптов
Причём, если мы просто укажим эту команду, то все предыдущие настройки, унаследованные от директорий выше сотрутся. 
Можно задавать относительные настройки, тогда перед каждой настройкой ставится либо '+' либо '-', обозначающие либо о включении, либо об отключении настройки (не затронутые настрйки не поменяются).

##### Контейнеры Files и Location
Хоть сначала они могут показаться похожими на контейнер Directory, но они всё же выполняют другие роли.
`<Files "file_name">...</Files>` - описывает правила для файлов с таким именем (любым, не важно какой путь)
`<FilesMatch "regex">...</FilesMatch>` - тоже самое, но применяет правила для всех подошедших под шаблон файлов
`<Location \dir>...</Location>` - описывает правила именно для директории URL и выше стоящих URL путей (хотя они могут хаотично распологаться на сервере в силу всех возможных `Alias`).

##### Контейнер IfModules
Это условный контейнер, конфигурация внутри него используется, если указанный модуль активирован:
```
<IfModule mod_rewrite.c>
	...
</IfModule>
```
