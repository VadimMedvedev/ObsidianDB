
Модуль `mod_rewrite` в Apache — это мощнейший механизм для манипуляции URL-адресами в реальном времени. Его часто называют "швейцарским ножом" или даже "вуду" из мира веб-серверов из-за его огромных возможностей и, как следствие, сложности

Как обычно, его для начала надо включить: `a2enmod rewrite`, а затем перезапустить apache: `systemctl reload apache2`.

### Директива RewriteEngine

Прописывая директиву `RewriteEngine On` в контейнере `<Directory>`, мы говорим, чтобы следующие написанные директивы этого модуля работали в этой директории и во всех вложенных. Если в какой-то вложенной директиве нам этого не надо, мы можем также и выключить выполнение этого модуля.

### Директива RewriteRule

Это основная директива, которая выполняет замену.
Синтаксис выглядит так:
```
RewriteRule <паттерн> <подстановка> [флаги]
```

Каждое правило, если оно нашло свой паттерн в URL заменяет URL на свою подстановку. Здесь используются регулярные выражения, как и при использовании директивы [[Виртуальные дирекотории и перенаправления Apache|RedirectMatch]]. Более того, здесь можно использовать [[Переменные в Apache|переменные Apache]].

Набор опций в квадратных скобках, управляющих поведением правила. Флаги разделяются запятыми:
- `[L]` (Last) — **Самый важный.** Если правило сработало, прекратить обработку остальных правил в этом файле.
- `[R]` или `[R=301]` (Redirect) — код статуса редиректа (можно поставить и `[R=302]`). Если данного флага нет, то редирект будет внутренним (т.е. браузер даже не узнает об подемене пути). 
- `[QSA]` (Query String Append) — Если в исходном URL были параметры (`?id=5`), добавить их к новому URL.
- `[NC]` (No Case) — Игнорировать регистр букв (A = a).
- `[F]` (Forbidden) — Вернуть ошибку 403.
- `[G]` (Gone) — Вернуть ошибку 410.

### Директива RewriteCond

`RewriteRule` сам по себе проверяет только путь (URL). Но часто нужно проверить что-то еще: тип браузера, наличие HTTPS, имя хоста и т.д. Для этого используется `RewriteCond`.
`RewriteCond` относится **только к следующему за ним `RewriteRule`**. Если условий несколько, они работают как логическое **И** (AND). Все условия должны быть истинны, чтобы правило сработало.
Синтаксис:
```
RewriteCond <проверяемая строка> <паттерн> [флаги]
```
Условие считается верным, если проверяемая строка (обычно переменные сервера) подходит по паттерну (заданный как обычно регулярным выражением). Тут тоже можно испольщовать флаги, но их только два:
- `[NC]` (No Case) — Игнорировать регистр букв (A = a).
- `[OR]` — логическое ИЛИ. По умолчанию условия связываются через И.
Обычно в качестве проверяемой строки выступает [[Переменные в Apache|переменная окружения Apache]].

### Дополнительные штуки

* При указании в `RewriteRule` второго парметра как `-`, URL менятся не будет.
* Перед паттерном в `RewriteCond` мы можем поставить `!`, это будет как логическое нет.
* В директиве `RewriteCond` есть специальная группа флагов, которые проверяют не регулярное выражение, а **состояние файла или URL** в операционной системе. Они пишутся в поле `паттерн`:
	* `-f` - Проверяет, существует ли объект и является ли он **обычным файлом**.
	* `-d` - Проверяет, существует ли объект и является ли он **директорией**.
	* `-l` - Проверяет, является ли объект **символической ссылкой**.
	* `-s` - Проверяет, существует ли файл и его размер **больше 0 байт**.
	* `-F` - Файл существует **И** доступен для обработки текущим пользователем Apache (проверяет права ОС и `.htaccess`).
	* `-U` - URL существует и доступен (делает внутренний подзапрос).
* Можно делать конструкции по типу `!-f` (т.е. истенно, если такого файла нет).
* Директвиа `RewriteBase` указывает Apache, какой префикс пути нужно считать корнем для текущих правил.

### Примеры

```
RewriteEngine On
# Если HTTPS не включен
RewriteCond %{HTTPS} off
# Перенаправить на тот же хост и URI, но с https
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
```

```
RewriteEngine On
# Если агент содержит "BadBot"
RewriteCond %{HTTP_USER_AGENT} BadBot [NC]
# Запретить доступ (403)
RewriteRule ^ - [F]
```

```
RewriteEngine On
RewriteBase /
# Если это не реальный файл (-f)
RewriteCond %{REQUEST_FILENAME} !-f
# И не реальная директория (-d)
RewriteCond %{REQUEST_FILENAME} !-d
# Перенаправить внутренний запрос на index.php, сохранив путь в параметре
RewriteRule ^(.*)$ index.php?q=$1 [L,QSA]
```
