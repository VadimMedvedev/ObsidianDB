
HTTP-кэширование — это механизм, который позволяет клиентам (браузерам) или промежуточным серверам (CDN, прокси) хранить копии ресурсов (HTML, CSS, JS, картинки и т.д.) для повторного использования без обращения к исходному серверу.

Цели кэширования:

- **Снижение нагрузки на сервер**
- **Уменьшение времени загрузки страницы**
- **Экономия трафика**

### Заголовки кэширования

Работа кэширования устроена на заголовках. Они прикрепляются к ответам сервера:
* Cache-Control — основной современный инструмент кэширования.
* Expires — устаревший способ задания срока жизни ресурса.
* ETag — идентификатор версии ресурса.
* Last-Modified — дата последнего изменения ресурса.
* Vary — указывает, по каким заголовкам варьируется кеш (например, User-Agent, Accept-Encoding). Т.е. если какого-то заголовка нет, то при разных его значениях кеш будет одинаковым.

### Cache-Control

Это ключевой заголовок. Его можно использовать как в **ответах сервера**, так и в **запросах клиента**.
Этот заголовок может принимать сразу несколько параметров, которые записываются через запятую:

| Директива            | Описание                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------- |
| `public`             | Ресурс можно кэшировать любым кэшем (браузер, CDN, прокси), т.е. разрешение shared cache |
| `private`            | Кэшировать только в браузере пользователя, не в публичных прокси                         |
| `no-store`           | Ресурс **не должен** кэшироваться нигде (ни диск, ни память)                             |
| `no-cache`           | Ресурс **можно кэшировать**, но перед использованием нужно проверять у сервера           |
| `max-age=<seconds>`  | Максимальное время жизни ресурса в секундах с момента запроса                            |
| `s-maxage=<seconds>` | Максимальное время жизни только для **shared caches** (CDN, прокси)                      |
| `must-revalidate`    | После истечения `max-age` ресурс нужно обязательно проверять на сервере                  |
| `proxy-revalidate`   | То же самое, но для shared caches                                                        |
| `immutable`          | Ресурс не изменяется, можно не проверять его с сервером                                  |

Пример:
`Cache-Control: public, max-age=3600` — любой кэш может хранить ресурс 1 час.

### Условные заголовки 

Они используются для определения устаревашния кэша. Есть два таких заголовка:
`If-None-Match: "5d8c72a5edda9"`
Если ETag совпадает (т.е. ресурс не менялся), то сервер возвращает код статуса `304`. Аналогично можно проверить при помощи:
`If-Modified-Since: Mon, 09 Mar 2026 12:00:00 GMT`
Ответ сервера будет аналогичен, если с заданого времени ресурс не менялся.
