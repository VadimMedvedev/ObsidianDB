
В Apache есть три модуля mpm, которые полностью определяют принципы работы Apache. Они взаимоисключающие. В конфигурации должен быть включён ровно один.
1.  `mpm_prefork` - на каждое соединение с клиентом создаёт отдельный процесс. Использует много памяти, так как каждый процесс — это полная копия Apache. Но позволяет отделять процессы друг от друга - сломается один, другие продолжат работу.
2.  `mpm_worker` - также использует несколько процессов. Каждый процесс создает фиксированное количество потоков. Каждый поток обрабатывает одно соединение. **Более экономно расходует память**, чем prefork. Общий выбор для стабильных серверов со средним трафиком.
3. `mpm_event` - модуль на базе worker, который поддерживает соединения keep-alive (т.е. при котором TCP соединение может передавать сразу несколько запросов). Это современный стандарт. Он выделяет отдельные потоки для обработки "долгоживущих" соединений (Keep-Alive), не блокируя основные рабочие потоки.

Рассмотрим особые конфигурации для каждого модуля:
##### Prefork
`StartServers` - Количество дочерних процессов, создаваемых при старте сервера.
`MinSpareServers` - Минимальное количество незанятых (idle) процессов. Если их меньше, Apache создает новые процессы.
`MaxSpareServers` - Максимальное количество незанятых процессов. Если их больше, лишние процессы завершаются.
`MaxRequestWorkers` - Максимальное количество одновременных соединений, которое может обрабатывать сервер. Фактически — это максимальное количество дочерних процессов.
`ServerLimit` - Жесткий верхний предел для `MaxRequestWorkers`.

##### Worker и Event
`StartServers` - Количество дочерних процессов, создаваемых при старте сервера.
`MinSpareThreads` - Минимальное количество незанятых потоков.
`MaxSpareThreads` - Максимальное количество незанятых потоков.
`ThreadsPerChild` - Количество потоков, создаваемых в одном дочернем процессе.
`ThreadsLimit` - Аппаратный предел для `ThreadsPerChild`.
`MaxRequestWorkers` - Максимальное общее количество **потоков** (а значит и одновременных соединений), которое может обрабатывать сервер. По сути, это произведение количества процессов на количество потоков в каждом.
`ServerLimit` - Жесткий предел для количества дочерних **процессов**.

#####  Дополнительные для Event
`KeepAlive On` - включения возможности продолжительных соединений
`MaxKeepAliveRequests` - ограничивает количество запросов, которые можно отправить через одно Keep-Alive соединение. Рекомендуется устанавливать в значение, вдвое превышающее количество элементов на самой тяжелой странице сайта.
`KeepAliveTimeout` - Время в секундах, которое сервер ждет следующего запроса от клиента на открытом соединении.

##### Общие директивы
`MaxConnectionsPerChild` - после какого числа соединений процесс будет перезапущен. При значении `0` не будет перезапускатся. Перезапуск процесса помогает бороться с утечкой памяти
`Timeout` — таймаут операций ввода-вывода. При превышении процесс будет сбрасываться.
