
Файл **.htaccess** (Hypertext Access) — это файл конфигурации веб-сервера **Apache**, который позволяет управлять настройками сервера на уровне отдельной директории без необходимости редактирования основных конфигурационных файлов и перезагрузки службы.

### Принцип работы

**Иерархия:** Когда Apache получает запрос, он ищет файл `.htaccess` в запрашиваемой директории, а затем во всех родительских директориях вплоть до корня сайта.
**Наследование:** Правила из родительских `.htaccess` применяются первыми, затем правила из текущей директории. Правила в текущей директории могут переопределять правила родителей (в зависимости от директив).

Эти файлы переписывают конфигурацию из apache2.conf. Таким образом это гибкий метод настроить уникальные параметры для каждой директории.

В `.htaccess` можно прописывать все те же настройки, что и в контейнере `<Directory>` в `apache2.conf`, эти настройки будут применены именно к этой и вложенным директориям.

### Ограничение перезаписи

Иногда, перезапись через `.htaccess` может быть не желательной. Для регулировки использования файлов `.htaccess` мы используем директиву `AllowOverride` в файле `apache2.conf`. Она прописывается в контейнерах `<Directory>`, таким образом разграничиваются настройки применения файлов `.htaccess` в разных директоиях.
Пример:
```
<Directory "/var/www/html">
    AllowOverride All
</Directory>
```

Возможные значения директивы:

|Параметр|Описание|
|---|---|
|**None**|`.htaccess` полностью игнорируется. **Лучший вариант для производительности**, если вам не нужно менять настройки на лету.|
|**All**|Разрешены все директивы, которые могут быть в `.htaccess`. Удобно для разработки, но менее безопасно.|
|**AuthConfig**|Разрешает директивы контроля доступа: `AuthType`, `AuthName`, `AuthUserFile`, `Require`, `Allow`, `Deny`. Используется для защиты паролем.|
|**FileInfo**|Разрешает управление типами документов: `AddType`, `AddEncoding`, `AddLanguage`, `DefaultType`. Также включает `mod_rewrite` (RewriteEngine, RewriteRule).|
|**Indexes**|Разрешает управление листингом директорий: `Options Indexes`, `DirectoryIndex`, `HeaderName`, `ReadmeName`.|
|**Limit**|Разрешает ограничение доступа к ресурсам: `Allow`, `Deny`, `Order`.|
|**Options**|Разрешает использование директивы `Options` (например, `FollowSymLinks`, `ExecCGI`).|
|**Override**|(Apache 2.4+) Позволяет контролировать переопределение конкретных настроек конфигурации.|
Таким образом параметр `All` разрешает все действия, но для безопасности следует прописывать возможности перезаписи более точно. Например если нам нужно управлять только настройками аутентификации и листингом, лучше прописать директиву так: `AllowOverride AuthConfig Indexes`.
