
Методы HTTP (HTTP-глаголы) - это набор команд, который клиент может отправить серверу, чтобы указать желаемое действие над ресурсом.
В RFC 2616 было всего 8 методов, но сейчас их гораздо больше.

### Основные методы

Вот основные методы:
* GET - Запросить представление ресурса. После пути ресурса в URL могут также указываться параметры передачи. Они перечисляются после `?` и разделяются знаком `&`. Пример: `/search?q=http&page=2`. Не подходит для передачи чувствительных данных.
* HEAD - Получить заголовки ответа (по сути GET но без тела). Это используется для проверки существования ресурса и получения его мета данных без полной передачи данных.
* POST - отправить данные на обработку. Обычно используется для отправки HTML форм, загрузки файлов и создания новых ресурсов. Не имеет ограничения на размер данных.
* PUT - загрузить или полностью заменить ресурс. Если не было - создаст, если было, то заменит.
* DELETE - удалить ресурс.
* OPTIONS - узнать, какие методы и опции поддерживает сервер для ресурса
* TRACE - вернуть полученный запрос. Испольщуется для диагностики (например происходит ли редерект, меняет ли прокси запрос). Часто отключают ради безопасности.
* CONNECT - установить тунель через прокси сервер. При этом пользователь присылает такой запрос с указанием нужного сервера, прокси усатанвливает с ним TCP соединение и отправляет клиенту код 200. После чего происходит дальнейшая пересылка.
* PATCH - частичное обновление.

Основные характеристики методов перечислены в таблице ниже. Здесь подразумевается:
* Безопасности - действия метода не влияют на сервер (read-only)
* Кэшируемость - можно кэшировать ответ
* Идемпотентность - многократное выполнение возвращает один и тот же ответ

| Метод   | Безопасность | Идемпотентность | Кэш | Тело ответа | Тело запроса    |
| ------- | ------------ | --------------- | --- | ----------- | --------------- |
| GET     | да           | да              | да  | да          | нет             |
| HEAD    | да           | да              | да  | нет         | нет             |
| POST    | нет          | нет             | нет | да          | обычно да       |
| PUT     | нет          | да              | нет | да          | возможно        |
| DELETE  | нет          | да              | нет | обычно нет  | возможно        |
| OPTIONS | да           | да              | нет | нет         | возможно        |
| TRACE   | да           | да              | нет | нет         | получен. запрос |
| CONNECT | нет          | нет             | нет | нет         | нет             |
| PATCH   | нет          | нет             | нет | да          | возможно        |

### Методы WebDAV (RFC 4918)

Методы WebDAV были добавлены для управления файлами на сервере
* PROPATCH - создать, изменить свойства ресурса
* PROFIND - получить свойста ресурса
* MKCOL - создать коллекцию (папку)
* COPY - копирование ресурса
* MOVE - перемещение ресурса
* LOCK - блокировка ресурса
* UNLOCK - разблокировка ресурса

Кроме этих методов конечно есть и другие. Их постепенно добавляют.
