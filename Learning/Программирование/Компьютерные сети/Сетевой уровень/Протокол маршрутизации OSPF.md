
Этот протокол пришёл на смену устаревшему RIP. 
RIP подходил только для маленьких сетей. Каждое устройство с RIP рассылало известные ему сети, причём расстояния между сетями измерялась в хопах (переходах с маршрутизатора на маршрутизатор). Это оказалось не достаточно эффективно.
Плюс OSPF что он работает на всех сетевых устройствах, в отличии от проприетарных аналогов.
Более того OSPF умеет работать не только с IPv4 (OSPFv2), но и с IPv6 (OSPFv3). Принципы работы в третьей версии остались такими же.

### Компоненты OSPF

OSPF между устройствами обменивается служебными сообщениями, среди них:
* Пакет приветствия (Hello) - выполняет обнаружение смежных устройств
* Пакет описания БД (DBD) - проверяет синхронизацию БД
* Пакет состояния канала (LSR) - запрос на данные из БД
* Пакет обновления состояния канала (LSU) - передача данных БД. Также использвется для пересылки обновлений маршрутизации. В нём может храниться 11 различных типов объявлений состояний (LSA).
* Пакет подтверждения состояния канала (LSAck) - Подтверждает пакеты DBD, LSR и LSU.

Также на каждом устройстве есть несколько БД, которые хранят информацию:
* БД смежности - список всех соседних маршрутизаторов
* БД состояния каналов (LSDB) - содержит данные обо всех маршрутизаторах в сети
* БД пересылки - маршруты созданные на основании LSDB. Для этого используется алгоритм SPF (поиска кратчайшего пути).

### Принципы работы

1. Установление отношений смежности
2. Обмен состояниями каналов. Оно распространяется по сети по всем маршрутизаторам
3. Создание базы данных состояния связи
4. Исполнение алгоритма SPF
5. Выбор лучших маршрутов

При каждом изменении в сети обновление рассылается на остальные маршрутизаторы и происходит перерасчёт кратчайших маршрутов.

### Области OSPF

Для того чтобы каждый маршрутизатор не хранил все маршрутизаторы в нашей огромной компании в своей памяти, и постоянно не перестраивал свои маршруты при каждом новом, сети разделяются на области, внутри которых работает протокол.

Плюсы:
* Меньший размер таблицы маршрутизации
* Реже происходит обновления состояний каналов в сети
* Реже происходит расчёт SPF
Итого весь процесс сильно убыстряется

Протокол OSPF для нескольких областей работает следующим образом. Все области должны быть подключены к магистральной области (область 0). Маршрутизаторы соединяющие области называются граничными (ABR).

### Пакеты OSPF

Они обеспечивают общение между маршрутизаторами в области. В каждом заголовке OSPF пакета прописывается:
1) Версия (2 или 3)
2) Тип пакета. Каждому выше описанному пакету соответствует свой номер
3) Длина пакета
4) ID маршрутизатора отправителя. Оно специальным образом генерируется. Это 32  битное число. Они записываются как и IPv4 адреса
5) ID области
6) Сумма
7) Поля аутентификации
В зависимости от типа пакета, эти поля могут пропускаться и иметь спецефические значения

##### Пакет Hello

Используется для обнаружения соседей и установление параметров смежности.
Основные компоненты заголовка hello:
* Типа пакета = 1
* Указывает ID маршрутизатора и области
* Не использует поля аутентификации
Тело пакета:
1) hello interval - как часто ходят сообщения (если один из маршрутизаторов не получит во время hello пакет, то начнёт проверять)
2) dead interval - по умолчанию 4 hello интервала. Т.е. не получив 4 раза hello пакет считаем маршрутизатор умершим и пересчитываем топологию
3) Список смежности - деляться своими соседями
4) Выбранный маршрутизатор (DR) - обмениваются текущей информацией о нём. Выбирается с наибольшим значением router ID
5) Запасной маршрутизатор (BDR) - аналогично, но выбирается второй по величене ID маршрутизатор.
### Состояния протокола

* Состояние Down - не получает hello пакетов. Он сам начинает отправлять hello пакеты на все порты, тем самым переходит в состояние init. Для пересылки пакетов используется unicast адрес специально зарезервированный для OSPF, его читают только устройства с OSPF и находящиеся в одной области. Это адрес 224.0.0.5.
* Состояние Init - получает ответы от соседних маршрутизаторов. Маршрутизатор  переходит в режим two-way
* Состояние Two-Way - связь между двумя маршрутизаторами установлена двустороняя. Начинается выбор DR и BDR. Переходит в состояние exstart
* Состояние ExStart - определение кто кому будет слать DBD пакеты, дабы разобраться в текущей топологии
* Состояние Exchange - пересылка пакетов DBD. Если знания не достаточны переход в состояние Loading, инчае Full
*  Состаяние Loading - пересылка пакетов LSR и LSU. После полной синхронизации переходит в состояние Full
* Состояние Full - маршрутизаторы синронизировались и готовы обрабатывать пользовательский трафик. Но всё равно через каждые 30 минут происходит проверка синхронизации баз данных.

Самые главные и продолжительные состояния two-way и full. Если настройка OSPF затянулась на другом состоянии, это сигнализирует о какой-то поломке.

### Маршрутизаторы DR и BDR

Если мы соединяем несколько маршрутизаторов коммутатором, то каждый начинает себя считать смежным с каждым. При большем числе маршрутизаторов число смежностей очень сильно увеличивается.
Чтобы упростить этот процесс всетях выбираются два маршрутизатора главый (DR) и вспомогательный (BDR). Причём BDR становится DR после смерти текущего DR. 
Все маршрутизаторы в локальной сети считают себя смежными только с DR, что намного уменьшает количество смежностей. Таким образом каждый маршрутизатор обменивается информацией только с DR.
При этом через DR будет проходить только настройка OSPF, передача не служебных данных в сетях коллективного доустпа (ну т.е. в LAN) будет происходить как обычно.

Определение DR и BDR:
1) Маршрутизатор с наибольшим приоритетом становиться DR, второй BDR
	* Приоритуты от 0 до 255
	* 0 - не участвует в выборах
	* 1 - приоритет по умолчантю у всех
2) По Router ID, у кого больше

### Метрика

Стоимость подключения определяется из формулы:
$$Стоимость = 100\ 000\ 000\ бит/с\ \ \ /\ \ \ пропускная\ способность\ бит/с$$
 Хотя значение 100000000 - эталонная пропускная способность может меняться, это значение по умолчанию.
Поитогу метрика маршрута это просто сумма стоимостей каждого участка маршрута. Алгоритм SPF опираясь на стоимости находит наикратчайший.
