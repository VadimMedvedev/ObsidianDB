
Протокол передачи данных. Его основные действия
* Подтверждение полученных данных
* Повторная отправка при необходимости
* Нумерация сегментов и определния их порядка.

Особенности:
* Надёжность
* Подтверждение данных
* Повторная отправка
* Доставка данных в порядке их отправления

Для кого следует использовать:
* Базы данных
* веб-браузеры
* электронная почта

### Общая картина работы TCP

Этот протокол устанавливает сеанс связи. 
Затем он каждый раз советуется со своим партнёром. Проверяет готов ли он к получению данных, нужно ли переотправить некоторые данные и т.д.
Договаривается с ним о скорости передачи данных, согласует объём пересылаемого трафика и т.д.

После каждой отправки сегмента данных включается счётчик, если в течении этого времени подтверждения их получения не пришло мы повторяем отправку.

### Заголовок TCP

Основные поля:
* Порт источника (16 бит, больше 2^16=65536 нельзя поставить сервисов на устройство)
* порт назначения (16 бит)
* порядковый номер, чтобы определять порядок пакетов доставляемых
* Номер подтверждения - используется для подтверждения получения данных
* Длина заголовка
* зарезервировано, не используються
* Управляющие биты, т.е. флаги, определяют разные режимы работы. Тумблеры:) Их 6 бит.
* Окно - сколько данных передавать можно без подтверждений. Когда объём переданной превышает размер окна, источник ждёт подтверждения от получателя, т.е. сегмента с флагом ACK.
* Контрольная сумма
* Срочность
* Опции

Причём тут нет длины всего пакета, мы получаем ограничения с нижних уровний (MTU). Через MSS получаем возможное количество данных помещаемых в сегмент, по сути это MTU - длины заголовков.

Для порта источника исользуется динамический номер порта, т.е. говорим в какую "дверь" отправлять данные в ответ.

### Установка соединения

Установление соединения в TCP — это процесс, который называется **Трехэтапное рукопожатие (Three-Way Handshake)**.
1. Клиент иницирует сесию. Он отправляет пакет с флагом SYN. Он устанавливает SEQ номер начала последовательности (в поле **порядковый номер**), обычно рандомное число.
2. Сервер соглашается и отправляет пакет с флагами ACK - согласие и SYN - для создания обратного соединения. Он также отправляет свой собственный SEQ с какого номера он будет отправлять байты. В поле **номер подтверждения** указывается SEQ клиента + 1, т.е. то что он получил все предыдущие байты и ждёт следующий + 1 байт.
3. Клиент наконец отправляет пакет с флагом ACK серверу и с номером подтверждения равным следующему ожидаемому байту.

### Прекращение сеанса связи

1. Клиент отправляет сегмент с флагом FIN
2. Сервер отправляет сегмент с флагом ACK, т.е. соглашается
3. Сервер отправляет сегмент с флагом FIN
4. Клиент соглашается, отпраавляет сегмент с ACK

### Управляющие биты

URG - указание срочности
ACK - флаг подтверждения, и поле подтверждения задействовано
PSH - функция push
RST - сбросить соединение, используется при возникновении какой либо ошибки в соединении.
SYN - создание соединения
FIN - больше нет данных от отправителя

На этих флагах кстати были придуманы некоторые способы атаки.

### Упорядоченная доставка

TCP сам располагает сегменты по порядку, согласна порядковому номеру байтов и отдаёт приложению.
Значение начала последовательности при инциализации соединения (ISN) представляет собой начальное значение байтов. При передаче нового сегмента это значение увеличивается на объём сегмента, и новый сегмент отправляется уже с новым порядковым номером. Таким образом получатель может раставить сегменты по порядку и увидеть пропажу сегментов.

### Размер окна и подтверждение

Размер окна - это количество сколько источник может передать без получения подтверждения. Оно определяется при установлении связи.
Т.е. источник передаёт сегменты пока окно ещё не до конца заполнено. 
Компьютер получатель зачастую не дожидается исчерпания окна и начинает отсылать подтверждения о получении (количество полученных байт + 1). Что сигнализирует что все пакеты доставлены.
Но посольку если из сегментов 1, 2 и 3 отправленных в одно окно 2 сегмент потеряется, то получатель скажет что он получил только первый сегмент, и отправителю придёться отправять 2 и 3 сегмент снова, хотя третий сегмент уже пришёл до получателя.
При возникновении таких ситуаций, обычно компьютер отправитель уменьшает окно, чтобы чаще удостоверяться в получении пакетов, и меньше их повторно отправлять.
