
По сути DNS сервера хранят простые пары ip адрес и доменное имя. 
Таким образом обычному пользавателю не нужно запоминать ip адрес сайта, а только его доменное имя (просто запоминающуюся последовательность символов). Приложению, которое получило такое доменное имя, достаточно просто спросить у DNS сервера какой ip у сервера с таким доменным именем и всё, нижние уровни могут спокойно пересылать на этот ip адрес данные.

Каждый раз когда DNS сервер получает вопрос от клиента, он сначала пытается разрешить (найти ip адрес) данное доменное имя по своим записям, иначе он пересылает этот вопрос другому DNS серверу, который мог бы знать.
Каждый раз сервер запоминает новые связи доменных имён и ip адресов, для повторных вопросов.

Пользовательские ОС также запоминают доменные имена и ip в кэше, для быстрой работы.

### Иерархия доменных имён

Есть несколько доменных зон:
* . - корневая доменная зона - в ней содержаться все доменные зоны уровня ниже
* .com - пример доменной зоны первого уровня (она принадлежит корневой, самой главной). Она содержит доменные зоны более низкого уровня. Они называются TLD, среди них выделяют:
	* gTLD - общие домены
	* ccTLD - национальные домены
	* new gTLD - новые родовые домены
* .google - доменная зона второго уровня (она принадлежит доменной зоне .com). Также называются SLD.
* www - название хоста в этой доменной зоне. Называются поддаменами, и используються уже для разделения одного сайта на логические части.
Таким образом доменное имя складывается из названий нескольких доменных зон. В итоге получается: `www.google.com.`.
Таким образом получается иерархическая система, которая в доменном имени идёт от частного к общему (от поддамена к корневому домену `.`).
Полное доменное имя содержит точку в конце - т.е. показатель корневого домена, но в современных браузерах эта точка опускается.


У DNS серверов также есть своя иерархия:
* **Сервера домена среднего уровня.** (.cisco.com)Они хранят записи по типу `www.cisco.com`
* **Серверы домена верхнего уровня.** (.com) Они знают у каких dns сервером можно спросить, чтобы найти информацию про `cisco.com` и других. Для каждого TLD есть сразу несколько DNS серверов.
* **Корневые сервера** (.) хранят информацию только о dns серверах которые содержат доменные имена оканчивающиеся `.com` или `.org` и т.д. Их всего 13

### Принцип работы DNS

Все DNS серверы работают в двух режимах:
* Итеративный - когда на запрос отправляет соответсвующий ip адрес, если знает, а иначе отправляет в ответ адрес dns который ответсвенен за нужную доменную зону. Этот режим работает на больших dns серверах для уменьшения нагрузки.
* Рекурсивный - если не имеет записи о доменном имени, то сам обращается к dns серверу нужной доменной зоны, а затем только отправляет полученный результат. Такие сервера называются **серверами разрешения доменных имён (DNS resolver)**. Такие dns сервера, например, создают провайдеры для своих клиентов. В таких серверах обычно нет своих баз данных доменных имён, они хранят только кэш. Время хранения записи в кэше называется **TTL**.

Таким образом мы, как клиенты, обращаемся к DNS resolver серверами, которые сами скачут по нужным DNS серверам для разрешения имени, или же находят его из кэша.
Записи из кэша называются **не авторитетными**, а полученные из dns серверов авторитетными. Это связано с тем, что не авторитетные записи могут быть устаревшими.

### Записи на серверах

##### A - запись
Основная запись, определяющая соответсвие между доменными именем и адресом ipv4. Нескольким доменным именам можно присвоить один и тот же адрес (например если они находятся на одном сервере). Или же наоборот одному доменному имени можно указать несколько ip адресов, для распределения нагрузки между ними.
##### AAAA - запись
Аналог A-записи, но ставит в соотвестиве доменному имени ipv6 адрес.
##### CNAME - запись
Определеяет соответствие доменному имени другого имени. Другими словами это способ задать псевданим доменному имени.
##### MX - запись
Используется для почти
##### NS - запись
Указывает на доменные имена DNS-серверов для данного указанного доменного имени. Другими словами говорит имя сервера на котором надо искать его поддамены.
##### PTR - запись
Используется для соответсвия ip адресам их доменных имён. Т.е. при помощи них происходи обратное преобразование.
